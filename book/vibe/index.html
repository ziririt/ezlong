P05-01
규칙 파일에 넣는 사용량 규칙
## 사용량 규칙
· 큰 작업(파일 10개 이상 수정, 빌드 반복, 폴더 전체 조사, 새 라이브러리 도입) 전에는 먼저 멈추고 다음을 보고한 뒤 내 승인을 받는다: 무엇을 얼마나 만지는지, 왜 필요한지, 더 작게 할 방법이 있는지.
· 같은 오류를 두 번 고쳐도 안 되면 세 번째 시도 대신 멈추고, 원인 후보와 다음 계획을 보고한다.

14장 — 제출 자동화

P14-01

왜: AI는 확인하려고 파일을 열어 보여 주는 습관이 있다. 열쇠는 보여 주면 안 된다. 이 한 줄이 그것을 막는다.

P14-02
제출 자동화 스크립트 — 확인 단계 포함
App Store Connect API로 심사 제출을 자동화하는 스크립트를 ~/.appstoreconnect/ 에 만드세요. 조건: 열쇠 값과 ID는 스크립트에 쓰지 말고 같은 폴더의 설정 파일에서 읽을 것. 절차는 판 확인/생성 → 릴리스 노트(파일) 반영 → 최신 처리 완료 빌드 연결 → 제출 묶음 생성 → 항목 추가 → 제출 → 상태 재조회 보고. 실제 제출 전에 "지금 제출하면 이 판·이 빌드·이 노트"를 보여 주고 제 "제출" 신호를 기다리는 확인 단계를 넣을 것. 먼저 제출 없이 조회만 하는 시험(앱 목록 가져오기)으로 열쇠가 작동하는지 보여 주세요.

왜: 자동화는 실수도 자동으로 한다. 제출 직전에 한 번 멈춰 사람이 본다. 열쇠가 작동하는지는 안전한 조회로 확인하지 제출로 확인하지 않는다.

P14-03

왜: 스크립트가 있으면 제출은 이 한 줄. 확인 화면에서 "제출"이라고 해야 나간다. 밖에서 폰으로 시키지 않는다.
