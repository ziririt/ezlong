# 앱 소개 추가 가이드 — ezlong.com/app 과 앱 글로벌 헤더

- 작성: 2026-11-09(월) · 기준 커밋 `dec41774ab` 시점의 실물을 읽고 썼다
- 읽는 사람: 이 저장소에서 **새 앱을 앱 모음(`ezlong.com/app/`)과 앱 글로벌 헤더에 올리는 AI 작업자**(Claude, Codex, 그 밖). 이전 대화의 기억이 없다고 보고, 이 문서만으로 끝까지 할 수 있게 썼다.
- 이 문서는 사이트에 나가지 않는다(`firebase.json` 의 ignore 에 `**/*.md`). 다만 **저장소가 공개**이므로 이 문서와 커밋 메시지에 개인 호칭·계정 이메일·개인 폴더 경로·매출 수치를 적지 않는다. 소유자는 "오너"로 적는다.
- 상위 규칙은 이 저장소의 `CLAUDE.md`. 이 문서와 어긋나면 `CLAUDE.md` 가 이긴다.

## 0. 한 줄 요약

- 새 앱 하나를 올리는 일은 **여섯 군데를 함께 고치는 일**이다. 하나라도 빠지면 헤더와 목록과 검색엔진 정보가 서로 다른 말을 한다.
  - (1) `app/apps-nav.js` 의 `APPS` 배열에 한 줄
  - (2) `app/index.html` 본문에 카드 하나
  - (3) `app/index.html` 머리의 JSON-LD `ItemList` 에 항목 하나
  - (4) `app/index.html` 머리의 `title`·`description`·`keywords`·`og:title`·`og:description` 에 앱 이름
  - (5) 이미지: `app/icons/icon-XX.jpg` 한 장, `app/shots/XX-1.jpg` … 3~5장
  - (6) 그 앱에 자기 소개 페이지가 있으면, 그 페이지의 `<body>` 바로 다음 줄에 헤더 스크립트 한 줄
- **push 가 곧 라이브 배포다**(GitHub Actions → Firebase). 화면이 바뀌는 push 는 오너에게 미리보기를 보여 주고 확인을 받은 뒤에 한다.

## 1. 지금 구조 (2026-11-09 실측)

### 1-1. 파일

- `app/apps-nav.js` — 앱 글로벌 헤더의 **단 하나의 원본**. 앱 목록(`APPS`)이 여기 있다. 이 파일을 부르는 모든 지면의 헤더가 이 한 파일로 바뀐다.
- `app/index.html` — 앱 모음 페이지. 카드는 검색엔진이 읽어야 해서 **HTML 에 직접** 적는다(스크립트로 그리지 않는다).
- `app/icons/` — 헤더와 카드가 같이 쓰는 아이콘. 120×120 JPEG(약 4~9KB), `icon-sd.svg` 하나만 SVG.
- `app/shots/` — 카드 가로 스크롤 스크린샷. 최근 것은 276×600 JPEG(약 22~39KB). 화면에서는 높이 300px 로 그려지니 두 배 밀도다.
- `app/ezscan/` — ezScan 앱의 소개·개인정보처리방침·지원 페이지(2026-11-06 생성). **아직 헤더와 카드에는 올라가 있지 않다.** 이 문서의 첫 적용 대상일 가능성이 크다(7절 주의 사항 참고).
- `app/page.tsx`, `app/layout.tsx`, `app/globals.css` — 옛 Next.js 흔적. 이번 일과 무관하니 건드리지 않는다.

### 1-2. 헤더에 올라 있는 순서 (APPS 배열 순서)

- `ezlong` — EZLONG 투자도구, `/`, 아이콘 `icon-ez.jpg`. 본체 사이트로 가는 길만 둔다. 카드는 없다.

### 1-4. 헤더가 붙어 있는 지면

- ezlong 안: `/app/`(위에 고정, `data-sticky="1"`), `/longtime/`, `/skybluenote/`

### 1-5. 잠시 끈 곳 (PAUSED)

- `apps-nav.js` 의 `var PAUSED = ['insightimes.com'];` — 오너 결정(2026-11-04): 인사이트타임스 지면에서는 앱들이 모두 안드로이드에 등록된 뒤에 다시 띄운다.
- **오너가 말하기 전에는 이 목록을 건드리지 않는다.** 새 앱을 더하는 일과 무관하다.

## 2. 시작 전에 받을 재료

확인되지 않은 것은 지어내지 않는다. 비어 있는 칸은 비워 둔 채 오너에게 묻는다.

- **스토어 등록 이름**: 한국어, 영어, 일본어, 중국어. 헤더와 카드 이름은 스토어 등록명을 따른다(배터리 라이프·포토 타임이 그 예).
- **분류 한 줄**(카드의 `kind`): "명사 · 명사" 형식. 예: `충전 · 시계`, `사진 · 편집`, `웹 · 파일 전송`.
- **소개 문단**: 3~4문장. 앱 저장소의 스토어 문서(예: `docs/store/`)나 소개 페이지에서 가져오고, 화면에 실제로 있는 기능만 쓴다.
- **스토어 주소와 상태**: App Store 앱 아이디(`https://apps.apple.com/kr/app/idNNNNNNNNNN`), Play 패키지 이름, Mac App Store 주소. 상태는 넷 중 하나 — 출시 / 테스트 중 / 준비 중 / 개발 중.
  - **아직 심사를 통과하지 않은 앱에 스토어 링크를 걸지 않는다.** 앱 기록만 만들어진 아이디는 열면 "찾을 수 없음"이 뜬다.
- **지원 기기 배지 한 줄**: 예 `iPhone · iPad`, `오래된 아이패드도 · iOS 15부터`.
- **아이콘 원본** 한 장(정사각, 1024px 이상이면 좋다).
- **스크린샷 원본** 3~5장(세로). 화면에 개인 이름·사진·연락처가 보이면 쓰지 않는다.
- **소개 페이지 주소**(있으면). 없으면 LongLong 처럼 카드 자체가 소개다.
- **두 글자 접두어**: 아이콘·스크린샷 파일 이름에 쓴다. 이미 쓰는 것: `ez it lt sn bl pt ll sd`. 겹치지 않게 정한다(예: ezScan 이면 `es`).
- **아이디(id)**: 영문 소문자 한 낱말. `APPS` 의 `id`, 카드의 `id`, 헤더 링크 `#id` 가 모두 이것을 쓴다(예: `ezscan`).

## 3. 이미지 만들기

- 아이콘: 120×120 JPEG, 품질 85 안팎, 10KB 아래. 모서리는 CSS 가 둥글리니 **사각 원본**으로 만든다. 맥에서:
  - `sips -s format jpeg -s formatOptions 85 -z 120 120 원본.png --out app/icons/icon-XX.jpg`
- 스크린샷: 높이 600px JPEG, 품질 80 안팎, 장당 40KB 아래. 가로는 비율을 따른다(아이폰 세로 화면이면 276 안팎).
  - `sips -s format jpeg -s formatOptions 80 --resampleHeight 600 원본.png --out app/shots/XX-1.jpg`
- 파일 이름은 `XX-1.jpg` 부터 차례로. 카드에 나오는 순서와 같게 한다.
- 만든 뒤 크기를 확인한다: `sips -g pixelWidth -g pixelHeight app/icons/icon-XX.jpg app/shots/XX-*.jpg`
- **이미지는 코드와 따로 먼저 커밋한다**(`CLAUDE.md` 1절 "이미지는 단독 커밋"). 같이 올리면 Firebase 에서 이미지가 깨져 보이는 틈이 생긴다.

## 4. `app/apps-nav.js` — APPS 에 한 줄

`longlong` 줄과 `send` 줄 사이에 넣는다. 모양(아래 예시는 ezScan 이고, 이름·접두어·주소는 2절에서 확인한 값으로 바꾼다. 같은 예시가 5·6절에도 이어진다):

```js
    { id: 'ezscan', name: 'ezScan', t: { en: 'ezScan', ja: 'ezScan', zh: 'ezScan' }, href: '/app/ezscan/',
      icon: '/app/icons/icon-es.jpg', here: ['/app/ezscan'] },
```

칸마다 뜻:

- `id` — 2절의 아이디. 카드 `id` 와 같아야 한다.
- `name` — 한국어 이름(스토어 등록명).
- `t` — 영어·일본어·중국어 이름. 한국어 이름과 모두 같으면 빼도 된다(없으면 `name` 을 쓴다). 한국어 이름이 한글이면 반드시 넣는다(배터리 라이프 줄이 그 예).
- `href` — 누르면 갈 곳.
  - 소개 페이지가 ezlong 안에 있으면 `/경로/` 처럼 **상대 주소**(ezlong.com 과 web.app 어디서 열어도 그 자리에서 움직이게).
  - 다른 도메인이면 `https://…` 전체 주소.
  - 소개 페이지가 없으면 `'/app/#아이디'`(카드로 보낸다).
- `icon` — `/app/icons/icon-XX.jpg`. 앞에 `/app/` 을 붙인 **절대 경로**로 쓴다. 다른 도메인에서 불려도 스크립트가 ezlong.com 기준으로 고쳐 준다.
- `here` — 그 앱 페이지에서 이 칸을 칠하기 위한 주소 조각.
  - ezlong 안이면 `'/경로'`(경로 앞부분만 비교).
  - 다른 도메인이면 `'호스트/경로 앞부분'`. 예: `'ziririt.github.io/batterylife-site'`, `'send.ezlong.com'`.
  - 소개 페이지가 없으면 `[]`.

건드리지 않는 것:

- `PAUSED`, `LABEL`, CSS 배열(`var css = [...]`), 언어 판정, 그리는 코드. 새 앱을 더하는 데는 필요 없다.
- 본체 투자 도구 헤더 `ez-nav.js` 와 섞지 않는다. 전혀 다른 파일이다.

고친 뒤 문법을 확인한다: `node --check app/apps-nav.js`

## 5. `app/index.html` — 카드 하나

`longlong` 카드(`<article class="card" id="longlong">`) 끝난 뒤, `send` 카드 앞에 넣는다. 기존 카드를 그대로 본뜬 틀:

```html
    <article class="card" id="ezscan">
      <div class="head"><img src="icons/icon-es.jpg" alt="" width="44" height="44" loading="lazy"><div>
      <p class="kind">문서 · 스캔</p>
      <h2><a class="plain" href="/app/ezscan/">ezScan</a></h2>
      </div></div>
      <p><a class="plain" href="/app/ezscan/" tabindex="-1" aria-label="ezScan 소개 보기">첫 문장은 이 앱이 무엇인지.
         둘째 문장은 가장 큰 기능 하나를 구체적으로. 셋째 문장은 다른 기능 두세 가지.
         넷째 문장은 누구에게, 어떤 때 좋은지.</a></p>
      <div class="shots">
        <figure>
          <a class="plain" href="/app/ezscan/" tabindex="-1">
          <img src="shots/es-1.jpg" alt="이 화면이 무엇을 보여 주는지 한 문장" loading="lazy">
          <figcaption>짧은 이름</figcaption>
          </a>
        </figure>
        <!-- 스크린샷 수만큼 figure 를 되풀이 -->
      </div>
      <div class="links">
        <a class="chip go" href="https://apps.apple.com/kr/app/idNNNNNNNNNN">App Store <small>무료</small></a>
        <a class="chip" href="/app/ezscan/">소개 보기</a>
        <span class="chip wait">Google Play <small>준비 중</small></span>
        <span class="badge">iPhone · Android</span>
      </div>
    </article>
```

규칙:

- `id` 는 `APPS` 의 `id` 와 같게. 헤더의 `/app/#아이디` 링크가 이 카드로 온다(고정 헤더에 가리지 않게 `scroll-margin-top` 이 이미 걸려 있다).
- 아이콘·스크린샷 경로는 이 페이지 기준 **상대 경로**(`icons/…`, `shots/…`).
- 링크 칩은 넷뿐이다. 새 모양을 만들지 않는다.
  - `chip go` — 지금 바로 받거나 여는 곳. `<small>` 에 `무료`, `설치 없이` 같은 한 낱말.
  - `chip` — 소개 페이지가 따로 있을 때만 `소개 보기`.
  - `chip wait` — 아직 없는 스토어. `<small>` 에 `준비 중` / `테스트 중` / `개발 중` 중 하나. `<a>` 가 아니라 `<span>`.
  - `badge` — 기기·특징 한 줄.
- 아직 어느 스토어에도 없으면 `chip go` 를 쓰지 않는다. 소개 페이지 `chip` 과 `chip wait` 만 둔다.
- 글: 합니다체, 3~4문장, 기능을 구체적으로. "최고의", "혁신적인" 같은 꾸밈말을 쓰지 않는다. 다른 카드들과 길이와 말투를 맞춘다.
- `alt` 는 화면이 무엇을 보여 주는지 한 문장, `figcaption` 은 2~6글자 명사구.
- 새 CSS 를 쓰지 않는다. 글자 14px 미만은 절대 금지다(`CLAUDE.md` 5절). 있는 클래스만 쓰면 지켜진다.
- 화면에 나가는 글에 개인 호칭, 내부 작업 사정, 자기 평가 문구를 쓰지 않는다. `scripts/check-privacy.py` 가 배포를 막는다(BANNED·INTERNAL·SELF_BLAME 목록).
- "다음 앱 자리" 점선 카드(`<div class="card soon">`)는 지우지 않는다. 늘 맨 끝에 둔다.

## 6. `app/index.html` 머리 — JSON-LD 와 메타

### 6-1. JSON-LD

`"itemListElement"` 배열에서 LongLong 항목 뒤, 초간단 파일공유 항목 앞에 넣는다. 그리고 **뒤에 오는 항목의 `position` 을 하나씩 민다**(지금은 send 가 7 → 8).

```json
      {
        "@type": "ListItem",
        "position": 7,
        "item": {
          "@type": "SoftwareApplication",
          "name": "ezScan",
          "alternateName": ["ezScan: One-Shot Doc Scanner"],
          "url": "https://ezlong.com/app/ezscan/",
          "applicationCategory": "UtilitiesApplication",
          "operatingSystem": "iOS, Android",
          "offers": { "@type": "Offer", "price": "0", "priceCurrency": "KRW" },
          "description": "카드 소개 문단을 한두 문장으로 줄인 것.",
          "installUrl": "https://apps.apple.com/kr/app/idNNNNNNNNNN"
        }
      },
```

- 스토어 앱은 `SoftwareApplication`, 웹 서비스는 `WebApplication`(이때 `"operatingSystem": "Web"` 과 `inLanguage` 를 넣는다. send 항목이 예).
- `applicationCategory` 는 schema.org 값에서 고른다: `UtilitiesApplication`, `MultimediaApplication`, `LifestyleApplication`, `ProductivityApplication`, `BusinessApplication` 등.
- `alternateName` 은 실제로 쓰는 다른 이름만 넣는다. 지어내지 않는다.
- 스토어에 없으면 `installUrl` 줄을 뺀다.
- 유료 구독이 있는 앱이라도 내려받기가 무료면 `price` 는 `"0"`. 화면에 없는 가격을 여기 적지 않는다.
- **구조화 데이터도 약속이다**(`CLAUDE.md` 4절): 화면 카드에 없는 기능이나 평점을 넣지 않는다.

### 6-2. 메타 다섯 줄

새 앱 이름을 다른 앱들 사이 같은 자리(LongLong 뒤, 파일 공유 앞)에 넣는다.

- `<title>` — "앱: EZLONG · 웹진, 노트, 시계, 충전, 사진 액자, 사진 이어붙이기, 파일 공유" 에 분류 한 낱말을 더한다(예: "문서 스캔").
- `<meta name="description">` — "… 스크린샷 이어붙이기 LongLong, (새 앱 한 구절), 코드 6자리 파일 공유 send.ezlong.com."
- `<meta name="keywords">` — 앱 이름과 분류 낱말 두세 개.
- `og:title`, `og:description` — 위와 같은 방식으로.

### 6-3. 공유 이미지(og) — 이번 범위 밖

- `og/og-app-1200x630.png?v=20260911` 에는 지금 **롱타임과 스카이블루 두 앱만** 그려져 있다(2026-11-04 에 더한 네 앱도 없다).
- 새로 그리는 것은 오너가 원할 때만 한다. 이번 작업에서는 바꾸지 말고, 끝나고 보고할 때 "공유 이미지가 두 앱 시절 그대로"라고 한 줄 적는다.

## 7. 소개 페이지에 헤더 붙이기

### 7-1. 붙이는 법

- 소개 페이지의 `<body>` **바로 다음 줄**에:
  - ezlong 안: `<script src="/app/apps-nav.js"></script>`
  - 다른 도메인: `<script src="https://ezlong.com/app/apps-nav.js"></script>`
- 그 페이지에 자기 머리띠가 위에 고정돼 있으면 `data-sticky` 를 붙이지 않는다(둘이 겹친다). 자기 머리띠가 없는 페이지만 `data-sticky="1"`.
- 언어: `<html lang>` 을 보고 한국어·영어·일본어·중국어 이름을 고른다. 깃허브 소개 사이트처럼 `#ko` 같은 해시로 언어를 바꾸는 페이지도 해시를 먼저 보니 그대로 된다.

### 7-2. 남의 지면에 얹을 때 확인할 것

- 헤더는 `<div role="navigation" class="ezapps">` 로 그려지고, 모든 CSS 가 `div.ezapps` 아래로 묶여 있다. 2026-11-04 에 소개 사이트의 `nav a{…}` 규칙과 `querySelectorAll("nav a")` 스크립트가 헤더를 망친 일이 있어서 이렇게 바꿨다.
- 붙인 뒤 그 페이지를 열어 헤더 글자 크기·배경·칠해진 칸이 다른 지면과 같은지 눈으로 본다. 다르면 소개 페이지 쪽을 고치지 말고, `apps-nav.js` 의 리셋 규칙을 보강하는 쪽을 먼저 검토한다(그 경우 모든 지면에 영향이 가니 오너에게 미리보기를 보여 준다).

### 7-3. 주의 — `/app/` 아래에 있는 소개 페이지는 지금 칠해지지 않는다

- `apps-nav.js` 는 ezlong 의 `/app` 으로 시작하는 주소를 전부 "앱 모음 페이지"로 본다:
  - `onHub = … && /^\/app(\/|$)/.test(location.pathname)`
- 그래서 `/app/ezscan/` 같은 하위 페이지에 헤더를 붙이면 **자기 앱 칸이 칠해지지 않는다**(`here` 를 맞게 적어도).
- 고치는 법: 앱 모음 페이지 자체만 허브로 보게 좁힌다.
  - `/^\/app\/?(index\.html)?$/.test(location.pathname)`
- 이 수정은 모든 지면의 헤더를 바꾸는 일이니, 고친 뒤 `/app/`(칠해진 칸 없음이 정상), `/app/ezscan/`(ezScan 칸이 칠해짐), `/longtime/`(Long Time 칸이 칠해짐) 세 곳을 확인한다.

### 7-4. ezScan 소개 페이지에 대해 알아 둘 것

- `app/ezscan/index.html` 은 `<html lang="en">` 에 `#en`/`#ko` 해시로 언어를 바꾸고, 자기 `nav a` 를 `querySelectorAll("nav a")` 로 고친다. 헤더는 `div` 라 이 스크립트에 걸리지 않는다.
- 자기 머리띠가 고정이 아니니 `data-sticky` 는 붙이지 않는다.
- ezScan 은 2026-11-06 기준 판 0.1.0, **스토어 심사에 아직 내지 않았다**(ezScan 저장소 `HANDOFF.md`). 카드를 지금 올린다면 스토어 칩은 모두 `chip wait` 로 두고, 상태 낱말은 오너에게 확인한다.
- 소개 페이지가 짧다(본문 수백 자). `/app/` 아래는 사이트맵 밖(8절)이라 배포 검사에는 걸리지 않지만, 카드에서 이 페이지로 보내기 전에 소개를 채울지 오너에게 묻는다.

## 8. 사이트맵 — 넣지 않는다

- ezlong.com 의 사이트맵은 미국 주식 도구만 싣는다. 오너 결정: 같은 호스팅에 얹혀 있을 뿐인 앱 소개는 ezlong.com 의 콘텐츠가 아니다(`CLAUDE.md` 4절 "채운 뒤에 다시 얇아지는 것을 본다").
- `/app/` 과 그 아래는 `scripts/check-sitemap.py` 의 `OFF_TOPIC` 에 이미 들어 있다. 새 앱 소개를 `/app/아래/` 에 두면 따로 할 일이 없다.
- ezlong 안의 **다른 새 폴더**(예: `/newapp/`)에 소개 페이지를 만들면:
  - `sitemap.xml` 에 넣지 않는다.
  - `check-sitemap.py` 의 `OFF_TOPIC` 에 `('/newapp/', '앱 이름 소개')` 한 줄을 더한다.
  - `noindex` 를 걸지 않고 `robots.txt` 로 막지 않는다. 검색에서 찾아지는 편이 그 앱에 낫다. **사이트맵에서 빼는 것과 검색에서 죽이는 것은 다른 일이다.**

## 9. push 전 확인

모든 검사는 **종료 코드로 판정**한다. `| tail`, `| head` 로 결과를 자르면 실패가 가려진다.

```bash
cd <ezlong 저장소>
node --check app/apps-nav.js && echo "apps-nav 문법 통과"

python3 - <<'PY'
import json, re
s = open('app/index.html', encoding='utf-8').read()
m = re.search(r'<script type="application/ld\+json">(.*?)</script>', s, re.S)
d = json.loads(m.group(1))
items = d['mainEntity']['itemListElement']
print([(i['position'], i['item']['name']) for i in items])
assert [i['position'] for i in items] == list(range(1, len(items) + 1)), 'position 번호가 어긋남'
cards = re.findall(r'<article class="card" id="([a-z0-9]+)"', s)
print('카드:', cards)
assert len(cards) == len(items), '카드 수와 JSON-LD 항목 수가 다름'
PY

if python3 scripts/check-privacy.py && python3 scripts/check-sitemap.py; then
  echo "배포 검사 통과"
else
  echo "배포 검사에 막힘 — 고친 뒤 다시"
fi
```

화면 확인(필수):

- 저장소 뿌리에서 `python3 -m http.server 8080` 을 띄우고 `http://localhost:8080/app/` 를 연다(헤더 스크립트는 localhost 도 앱 모음으로 알아본다).
- 폭 390px(휴대폰)과 1280px(데스크톱) 두 가지로 캡처한다. 확인할 것:
  - 헤더 줄에 새 아이콘과 이름이 제자리(LongLong 다음)에 있다.
  - 헤더의 새 칸을 누르면 그 카드나 소개 페이지로 간다.
  - 카드의 아이콘·스크린샷이 모두 뜬다(404 없음). 스크린샷 줄이 가로로 넘긴다.
  - 페이지 전체에 가로 스크롤이 생기지 않는다.
- 소개 페이지에 헤더를 붙였으면 그 페이지도 같은 두 폭으로 캡처하고, 그 앱 칸이 칠해졌는지 본다.
- **이 캡처를 오너에게 보여 주고 확인을 받는다.** 확인 전에는 push 하지 않는다.

## 10. 배포 순서

1. 세션 시작 백업: `sh backup-before-session.sh`(저장소 뿌리). 완료 메시지를 본 뒤에 파일을 고친다(`CLAUDE.md` 1절).
2. 잠금: `OPS_RUNNER=<이름> ~/Developer/_ops/bin/lock.sh claim ezlong "앱 모음에 <앱 이름> 추가"`. 맥에서 `osascript` 로 부릴 때는 명령마다 앞에 `export OPS_RUNNER=…` 를 붙인다.
3. `git pull --no-rebase origin main`(ezlong 은 rebase 가 아니다).
4. 이미지 커밋: `git add app/icons/icon-XX.jpg app/shots/XX-*.jpg` → 커밋 → push. 이미지만으로는 화면이 바뀌지 않으니 이 push 는 먼저 해도 된다.
5. 코드 커밋: `git add app/apps-nav.js app/index.html`(+ 고쳤으면 소개 페이지, `scripts/check-sitemap.py`). `git add -A` 는 쓰지 않는다.
6. 9절 검사 통과와 오너 확인을 받은 뒤 push.
7. 라이브 확인(push 가 끝이 아니다):
   - GitHub Actions "Firebase Hosting 자동 배포" 가 초록인지.
   - `curl -s "https://ezlong.com/app/?v=$(date +%s)" | grep -c 'id="새아이디"'` 가 1 이상.
   - `curl -s https://ezlong.com/app/apps-nav.js | grep -c "id: '새아이디'"` 가 1. `.js` 는 캐시가 600초라 **10분까지는 옛것이 보일 수 있다.** 10분이 지나도 옛것이면 `https://ezlong-541a8.web.app/app/apps-nav.js` 와 비교한다(`CLAUDE.md` 1절 "배포는 라이브 확인까지가 한 덩이다"). "캐시 지워라"를 첫 대응으로 하지 않는다.
   - 다른 지면 하나(예: 배터리 라이프 소개 사이트)를 열어 헤더에 새 앱이 생겼는지 본다.
8. 체크포인트 태그: `git tag cp-YYYYMMDD-app-새아이디 && git push origin cp-YYYYMMDD-app-새아이디`(`CLAUDE.md` 30항).
9. 잠금 풀기: `lock.sh release ezlong`. 커밋 해시와 확인 결과를 보고한다.

커밋 메시지 끝 두 줄(`CLAUDE.md` 1절):

```
Co-Authored-By: <작업한 모델 이름> <noreply@anthropic.com>
Claude-Session: <세션 주소, 없으면 출처 이름>
```

되돌리기: 오너가 "되돌려"라고 하면 `git checkout <직전 cp- 태그> -- app/apps-nav.js app/index.html` 후 새 커밋으로 push 한다. 히스토리를 고치지 않는다.

## 11. 하지 말 것

- 다른 앱의 카드·문구·순서를 함께 고치기(요청받지 않은 정리 금지)
- 각 지면에 붙은 헤더 스크립트 한 줄을 지우거나 옮기기
- `PAUSED` 목록 바꾸기(오너 말이 있을 때만)
- 스토어 심사를 통과하지 않은 앱에 스토어 링크 걸기, 화면에 없는 기능 쓰기
- 사이트맵에 앱 소개 넣기, 앱 소개에 `noindex` 걸기
- 공유 이미지(og) 마음대로 바꾸기
- `ez-nav.js`(투자 도구 헤더)와 `apps-nav.js` 섞기
- 화면 글자를 14px 아래로 내리기, 새 CSS 클래스 만들기
- 오너 확인 없이 화면이 바뀌는 push
- `git add -A`, `git reset --hard`, force push
